# Запуск узла B-hydra из исходников (Ubuntu)

Пока ты запускаешь собранный бинарник `~/bhydra-node/B-hydra-Core-linux`.
Настоящий PoW (развилка на высоте `POW_FORK_HEIGHT`) появился уже после той
сборки, поэтому до следующего релиза узел надо запускать из исходников.

⚠️ Файл состояния остаётся прежним — `bhydra_chain.json` рядом с запускаемой
программой. Формат не менялся (`{difficulty, chain, mempool}`, поля блока те
же), коллектор сайта читает его как раньше.

## 1. Что поставить

```bash
sudo apt update
sudo apt install -y python3 python3-tk git build-essential
```

`python3-tk` нужен окну (`bhydra_gui.py`), `build-essential` — нативному
майнеру. Больше ничего: у ядра нет обязательных зависимостей.

## 2. Забрать исходники

```bash
cd ~
git clone https://github.com/vladislav957/B-hydra.git
cd B-hydra
git checkout real-pow
```

## 3. Собрать нативный майнер

⚠️ **Это не «ускорение», а условие работы.** Чистый Python даёт около
5 700 хеш/с — блок при калиброванной цели искался бы там больше двух недель.
Нативный майнер на этой же машине даёт миллионы хешей в секунду.

```bash
g++ -O2 -std=c++17 -pthread -I cpp -o bhydra_miner cpp/bhydra_miner.cpp
./bhydra_miner selftest        # должно ответить {"ok": true, ...}
```

Собранный файл достаточно положить рядом — майнер находит его сам.
Выключается переменной `BHYDRA_MINER=off`.

Заодно стоит собрать ускоритель подписи (необязательно, но приём транзакций
станет вчетверо быстрее):

```bash
g++ -O2 -std=c++17 -shared -fPIC -I cpp -o libbhydra_ec.so cpp/bhydra_ec_lib.cpp
```

## 4. Откалибровать цель развилки ПОД ЭТУ МАШИНУ

⚠️ **Сделать это надо ДО того, как цепочка дорастёт до `POW_FORK_HEIGHT`.**
Цель развилки — правило сети: поменяешь её после развилки, и уже добытые
послефорковые блоки станут невалидными.

```bash
python3 -m b_hydra.powcalib --threads 1
```

Инструмент покажет строку вида `POW_FORK_HASHRATE = 1_600_000`. Подставь её в
`b_hydra/blockchain.py`.

⚠️ Число округляется ВВЕРХ намеренно. Завысил — блоки идут реже цели, эмиссия
отстаёт, ничего страшного. Занизил — блоки посыплются чаще цели, а это ровно
тот выброс эмиссии, ради которого развилка и вводится.

`--threads` ставь равным тому, сколько ядер отдашь под майнинг (см. пункт 6).

## 5. Перенести состояние и запустить

```bash
cp ~/bhydra-node/bhydra_chain.json ~/B-hydra/
cd ~/B-hydra
python3 bhydra_gui.py
```

Проверить, что цепочка принята без потерь:

```bash
python3 -m b_hydra.cli chain | tail -3
```

Должна показать твою высоту и `валидна: True`. Если нет — **не майни поверх**,
пришли вывод: значит развилка задета неверно.

Без окна (сервер, ssh):

```bash
python3 -m b_hydra.api --p2p          # REST + узел сети
python3 -m b_hydra.cli mine BHY<твой-адрес>
```

## 6. Сколько ядер отдать майнингу

По умолчанию берутся **все ядра, кроме одного**: перебор грузит ядро на 100%
без пауз, и на B570e «все ядра» означают неотзывчивое окно и горячий корпус.

```bash
BHYDRA_MINER_THREADS=1 python3 bhydra_gui.py    # только одно ядро
```

## 7. Чего ждать после развилки

До `POW_FORK_HEIGHT` всё как раньше: блок раз в ~48,6 мин по расписанию.
⚠️ Таймер там оставлен намеренно — цель до развилки это 4 096 хешей, и без
расписания оставшиеся блоки добылись бы мгновенно, по 50 BHY каждый.

С высоты развилки расписание исчезает: блок публикуется в тот момент, когда
найден хеш ниже цели. В строке состояния идёт живой отчёт — сколько хешей
перебрано и сколько в среднем нужно.

⚠️ Доля спокойно переваливает за 100%, и это нормально: поиск блока не имеет
памяти, перебрав вдвое больше ожидаемого, ближе к цели не становишься.
Разброс времени блока большой — от минут до нескольких часов при среднем
48,6 мин.

## Если что-то пошло не так

| Симптом | Причина |
|---|---|
| `валидна: False` сразу после переноса | цепочка переросла `POW_FORK_HEIGHT`, а калибровка менялась после этого |
| блок ищется сутками | `POW_FORK_HASHRATE` завышен — пересними `powcalib` и поправь ДО развилки |
| блоки сыплются по нескольку в минуту | `POW_FORK_HASHRATE` занижен; это выброс эмиссии, останови майнинг |
| окно не открывается | нет `python3-tk` |
| `{"ok": true}` не печатается | майнер не собрался, работает чистый Python — блок не найдётся никогда |
