# Майнинг на видеокарте (OpenCL)

`bhydra_miner.cl` — перебор nonce на GPU. Мост — `b_hydra/gpu_miner.py`.

## Быстрый старт

Собирать НИЧЕГО НЕ НУЖНО: ядро компилирует драйвер видеокарты при запуске.

```bash
python -m b_hydra.gpu_miner        # список устройств, self-test, скорость
python -m b_hydra.cli mine BHY<адрес>   # видеокарта подхватится сама
```

Переменная `BHYDRA_GPU`:

```bash
BHYDRA_GPU=off      python -m b_hydra.cli mine …   # только процессор
BHYDRA_GPU=1        python -m b_hydra.cli mine …   # устройство №1
BHYDRA_GPU=nvidia   python -m b_hydra.cli mine …   # по части имени
```

Нужен только драйвер с поддержкой OpenCL — он идёт в комплекте с драйверами
NVIDIA, AMD и Intel. Ни CUDA, ни `pyopencl`, ни компилятора ставить не надо.

## Почему именно эта задача ложится на GPU

Перебор nonce — тысячи **независимых** попыток: work-item берёт своё число,
считает SHA-512 и молча выходит, если не повезло. Обмениваться данными между
собой им не нужно вообще, общая память нужна ровно на одно слово — флаг
«нашли». Это лучший случай для видеокарты, какой бывает.

Остальное в B-hydra на GPU **не ложится** и туда не поедет: подпись, проверка
цепочки и сеть — это короткие зависимые цепочки операций, там видеокарта
медленнее процессора.

## Как устроено

| | |
|---|---|
| Язык | OpenCL C — один и тот же на NVIDIA, AMD и Intel |
| Загрузка | `libOpenCL` через `ctypes`, без `pyopencl` (у проекта ноль обязательных зависимостей) |
| Компиляция | драйвером, во время запуска |
| Интерфейс | тот же, что у `native_miner.py`: `selftest`/`mine`/`benchmark` |

Из-за общего интерфейса `Block.mine_block(miner=…)` принимает GPU-майнер без
единой правки, а вместе с ним достаются даром **срезы по времени** (право
бросить блок, когда сосед прислал свой) и **проверка результата**.

Порядок выбора движка в `mine_block`: видеокарта → нативный майнер на всех
ядрах (`cpp/bhydra_miner.cpp`) → чистый Python.

## Подводные камни

⚠️ **nonce приписывается ДЕСЯТИЧНОЙ строкой**, как `str(nonce)` в Python, а не
восемью байтами числа. Возьми ядро двоичный nonce — хеши сходились бы сами с
собой, но не с сетью, и каждый добытый блок отвергался бы всеми.

⚠️ **Видеокарте не верят.** `Block._mine_native` пересчитывает хеш нашим кодом
и сверяет с порогом; расхождение — `ValueError`, а не молчаливый откат.
Поэтому ядро отдаёт наружу и сам дайджест: верни оно только nonce, Python
сравнивал бы свой хеш сам с собой, и ядро с ЧУЖИМ SHA-512 прошло бы проверку
незаметно.

⚠️ **Само собой берётся только настоящая видеокарта.** CPU-устройства OpenCL
существуют (POCL, драйверы Intel), но считают те же хеши на тех же ядрах, только
через драйвер, — молча подменять ими нативный майнер незачем. Явным
`BHYDRA_GPU=<номер>` можно взять любое.

⚠️ **Расписание раундов живёт в окне из 16 слов**, а не в массиве на 80.
Формула `W[i] = σ1(W[i−2]) + W[i−7] + σ0(W[i−15]) + W[i−16]` дальше 16 назад не
смотрит. Это 128 байт приватной памяти на work-item вместо 640; на видеокарте
приватная память — регистры, и при нехватке компилятор выселяет расписание в
глобальную память, после чего каждый раунд упирается в неё.

⚠️ **Устройство обязано быть little-endian** — слова состояния и цели кладутся
в буферы в порядке хоста. Проверяется явно, big-endian отвергается: отказ
честнее молчаливо неверного PoW.

⚠️ **Драйвер может отвалиться** посреди работы (перегрев, сброс, выгрузка
модуля). Это не повод потерять блок: перебор молча продолжается на процессоре.

## Что проверено, а что нет

Проверено — **правильность**, и её можно проверить без видеокарты. В тестах
(`tests/test_gpu_miner.py`) ядро выполняется на CPU-устройстве OpenCL и:

* дайджест сверяется с нашим SHA-512 **побайтово** — на длинах префикса вокруг
  границы блока (127/128/129 байт) и на разном числе цифр в nonce;
* пространство поиска сужается до **одного** nonce, поэтому ответ однозначен, а
  не «нашлось хоть что-то»; проверяется и обратная половина — не подошёл,
  значит не найден;
* добывается настоящая цепочка, и она проходит `is_chain_valid()`;
* врущий майнер обязан быть пойман.

⚠️ **НЕ проверено: живое железо.** Видеокарты в контейнере разработки нет.
Скорость на настоящем GPU, поведение драйверов NVIDIA/AMD/Intel и подбор
`work_size`/`per_item` под конкретную карту здесь проверить нечем — умолчания
подобраны на CPU-устройстве и являются разумной отправной точкой, а не
выверенным оптимумом.

## Замер (CPU-устройство OpenCL, 4 ядра — НЕ видеокарта)

```
чистый Python (наш SHA-512)      2 381 хеш/с
C++ на 4 потока              3 791 693 хеш/с
OpenCL, то же ядро           6 623 331 хеш/с
```

Число последней строки — не «выигрыш GPU», а лишь подтверждение, что ядро
работает: у настоящей видеокарты тысячи ядер вместо четырёх.
