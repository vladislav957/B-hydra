# B-hydra Wallet для Android

APK **собирается без Android SDK** — одной командой:

```bash
python -m b_hydra.apkbuild --out bhydra-wallet.apk
```

Нужен только JDK (`javac`, `jarsigner`, `keytool`) и доступ к Maven Central.
Android SDK не требуется: он нужен ровно ради одного шага — двоичного
`AndroidManifest.xml`, а его собирает `b_hydra/axml.py` (свой кодировщик, как
в проекте сделаны свой SHA, своя ECDSA, свой QR, свой PNG и свой X.509).

⚠️ Собранный APK **не запускался на живом телефоне** — здесь нет ни устройства,
ни эмулятора. Проверено другое: структура архива, разбор манифеста НЕЗАВИСИМЫМ
парсером (`pyaxmlparser`), собственные контрольные суммы DEX (Adler-32 и SHA-1),
подпись (`jarsigner -verify`) и **содержимое байт-кода** — таблицы методов DEX
читаются напрямую (`apkbuild.dex_references`).

Последнее не формальность. «Собралось» не значит «работает»: пропади из
исходника `setDomStorageEnabled`, javac и `dx` отработают молча, APK
установится и откроется — а приложение будет ТЕРЯТЬ приватный ключ при каждом
закрытии, потому что ключ живёт в `localStorage`. Поэтому список обязательных
вызовов (`apkbuild.REQUIRED_CALLS`) сверяется с тем, что реально попало в
`classes.dex`, и сборщик печатает результат строкой `вызовы`.

### Что нашлось на живом телефоне

Всё вышеперечисленное APK проходил — и всё равно не работал: приложение
запускалось и сразу падало на `net::ERR_CLEARTEXT_NOT_PERMITTED`. Причина —
неверный ресурсный id у `usesCleartextTraffic` в `axml.py` (стоял `0x0101076E`
вместо `0x010104EC`). Android такой атрибут ошибкой не считает, он его молча
игнорирует, а для `targetSdk ≥ 28` открытый HTTP запрещён по умолчанию — то
есть разрешение просто не доходило до системы.

Проверки этого не увидели, потому что сверяли карту ресурсов с нашей же
таблицей `ATTRIBUTE_IDS` — то есть таблицу саму с собой. Теперь ids
сверяются с `public.xml` платформы (`test_attribute_ids_match_the_platform_table`),
а атрибуты, которых в эталоне нет, из таблицы убраны: лучше ошибка сборки
«неизвестный атрибут», чем тихо потерянная настройка.

## Как проверить APK самому

```bash
python -m b_hydra.apkbuild --out bhydra-wallet.apk   # соберёт и проверит
unzip -l bhydra-wallet.apk                           # 5 файлов, ~5,5 КБ
jarsigner -verify bhydra-wallet.apk                  # → jar verified.
```

`jarsigner` ругнётся на «Invalid certificate chain» — это нормально и ожидаемо:
подпись **самоподписанная**, удостоверяющего центра у неё нет и быть не должно.
Android проверяет не цепочку доверия, а неизменность: подпись обязана совпасть
при обновлении приложения.

На телефоне (Android 7+):

1. включите установку из неизвестных источников для того приложения, из
   которого открываете файл (браузер, файловый менеджер);
2. откройте `bhydra-wallet.apk` → «Установить»;
3. запустите **узел** на компьютере в той же сети:
   `python -m b_hydra.api --host 0.0.0.0 --p2p`;
4. в приложении меню (⋮) → **«Адрес узла»** → впишите адрес компьютера,
   например `192.168.0.10:8000`, и нажмите ОК.

Адрес нужен **один раз и один**: остальные узлы кошелёк узнаёт сам через
`GET /api/nodes` и дальше переживает падение того, через который вошёл. Это
seed-подключение, только на уровне кошелька — узлом телефон стать не может,
в `WebView` нет сырых сокетов, а значит и нашего P2P-протокола.

⚠️ `--p2p` в пункте 3 обязателен, если компьютеров несколько: без него REST
отвечает про **свою изолированную цепочку**, и телефон увидит одну цепочку,
а компьютеры — другую. Из GUI то же самое включается кнопкой «Кошелёк для
телефона» на вкладке «Сеть».

Пункт 3 обязателен: приложение — это окно, сама страница кошелька лежит на
узле. Поэтому при первом запуске приложение сразу спрашивает адрес, а не грузит
`10.0.2.2:8000` — это адрес хозяйской машины **для эмулятора**, и на живом
телефоне он мёртв. Если узел не отвечает, вместо системной страницы ошибки
показывается свой экран с этими же шагами: `ERR_CONNECTION_REFUSED` не
подсказывает ничего, а причина почти всегда одна.

## Сначала: APK может вообще не понадобиться

Кошелёк — устанавливаемое веб-приложение (PWA). На телефоне достаточно открыть
`https://<адрес узла>/wallet` и согласиться на «Добавить на главный экран»:
появится обычная иконка, приложение откроется без адресной строки и будет
работать без сети. Это тот же кошелёк, что и в APK, только без установки файла.

⚠️ Браузер предложит установку только с **защищённого источника** — запускайте
узел с `python -m b_hydra.api --tls` (на `localhost` работает и без него).

APK нужен, если хочется раздавать файл, ставить без браузера или положить
приложение в магазин.

## Что делает это приложение

Ничего, кроме окна. Криптографии внутри нет: ключ, подпись транзакции и QR
считает сама страница кошелька на устройстве (`bhydra-sign.js`, `bhydra-qr.js`,
`bhydra-net.js`). Java-код здесь — это `WebView`, адрес узла и кнопка
«Обновить».

Так сделано намеренно. Вторая реализация подписи под Android означала бы третий
независимый код для одного формата (после Python и JS) — и третий источник
расхождений. В проекте есть правило сверять реализации байт-в-байт; плодить их
без нужды незачем.

Что важно в оболочке и легко упустить:

* `setDomStorageEnabled(true)` — **обязательно**: приватный ключ кошелька живёт
  в `localStorage`. Без этого приложение забывало бы ключ при каждом закрытии;
* `android:usesCleartextTraffic="true"` — Android с 9-й версии запрещает
  открытый HTTP, а узел в домашней сети обычно отвечает именно по HTTP.
  Для узла с настоящим сертификатом (`--tls`) это не нужно;
* адрес узла задаёт пользователь (меню → «Адрес узла») и он сохраняется:
  приложение не привязано к одному серверу.

## Как это устроено без SDK

APK — это ZIP из четырёх понятных частей, и каждая делается доступным средством:

| часть | чем собирается |
|---|---|
| `AndroidManifest.xml` (двоичный AXML) | `b_hydra/axml.py` — свой, с нуля |
| `classes.dex` | `dx` с Maven Central (официальный дексер Dalvik) |
| `META-INF/*` (подпись v1) | `jarsigner` из обычного JDK |
| сам архив | `zipfile` из стандартной библиотеки |

Компилирует `javac`, заголовки Android берутся из артефакта
`com.google.android:android` на Maven Central.

Два ограничения, и оба видны в коде:

* **ресурсов нет** (`resources.arsc` собирает `aapt2` из SDK). Поэтому в
  манифесте не должно быть ссылок `@mipmap/...` — сборщик их выбрасывает и
  говорит об этом, а приложение получает системную иконку;
* **подпись схемы v1**. С `targetSdk 30` Android требует v2, которую делает
  `apksigner` из SDK, — поэтому в манифесте стоит `targetSdk 29`. Для установки
  вручную этого достаточно; для магазина приложений нужен полный SDK.

## Сборка через Gradle (с Android SDK)

Этот путь даёт иконку и `targetSdk 34`. Нужен Android SDK и JDK 17+.

```bash
# иконки берём из проекта — они рисуются кодом, а не лежат картинками
python -m b_hydra.icon                 # создаст icon-192.png и icon-512.png
mkdir -p android/app/src/main/res/mipmap-xxxhdpi
cp icon-192.png android/app/src/main/res/mipmap-xxxhdpi/ic_launcher.png

cd android
gradle wrapper                          # если нет gradlew
./gradlew assembleDebug                 # → app/build/outputs/apk/debug/app-debug.apk
```

Отладочный APK ставится сразу:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Для релиза нужна своя подпись — отладочным ключом приложение раздавать нельзя:

```bash
keytool -genkey -v -keystore bhydra.jks -keyalg RSA -keysize 4096 \
        -validity 10000 -alias bhydra
# затем пропишите signingConfigs в app/build.gradle и:
./gradlew assembleRelease
```

## iPhone

APK туда не поставить, а сборка `.ipa` требует macOS, Xcode и платного
сертификата Apple. На iOS остаётся путь PWA: Safari → «Поделиться» →
«На экран Домой». Кошелёк там работает, включая офлайн-режим; недоступно только
сканирование QR камерой — в Safari нет `BarcodeDetector`, адрес придётся
вставить вручную.

## Чего в оболочке нет

* Уведомлений о входящих платежах — для них нужен фоновый опрос узла.
* Резервного копирования ключа в облако: `allowBackup=false` намеренно, чтобы
  приватный ключ не уехал в чужое хранилище.
* Биометрической защиты входа. Ключ лежит в `localStorage` открытым — как и в
  браузере. Это следующий шаг и для PWA, и для APK.
