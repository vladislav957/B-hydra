# B-hydra Wallet для iPhone

> ⚠️ **`.ipa` здесь собрать НЕЛЬЗЯ, и это не вопрос смекалки.** Для Android
> оказалось достаточно найти обходной путь — там подпись **самоподписанная**, и
> APK, собранный чем угодно, установится. На iOS иначе: подпись обязана
> восходить к удостоверяющему центру **Apple**, сертификат выдаёт Apple
> конкретной учётной записи разработчика, а профиль обеспечения перечисляет
> устройства поимённо. Проверяет это ядро (AMFI) — неподписанное приложение
> просто не запускается. Обойти это без Apple невозможно **по устройству
> системы**, а не по недостатку инструментов.
>
> Плюс к этому: в окружении, где написан код, нет ни Swift, ни Xcode, ни iOS
> SDK, а `download.developer.apple.com` закрыт. SDK не распространяется
> отдельно и существует только для macOS.
>
> **Что это значит на практике:** файлы ниже — готовый проект, который
> собирается на Mac с Xcode. Он не компилировался и не запускался.

## На iPhone кошелёк уже работает — без всякого .ipa

Откройте `https://<адрес узла>/wallet` в Safari → «Поделиться» → **«На экран
«Домой»»**. Появится иконка, приложение откроется без адресной строки и будет
работать без сети. Это тот же кошелёк.

Кошелёк сам подсказывает этот путь на iPhone: Safari не умеет предлагать
установку кнопкой (события `beforeinstallprompt` в нём нет), поэтому подсказка
показывается отдельно — иначе владелец iPhone не узнал бы о такой возможности
вовсе.

⚠️ **Сохраните ключ.** Safari чистит хранилище сайта примерно через 7 дней без
визитов (ITP). У приложения, добавленного на главный экран, срок не действует,
но пока кошелёк открыт «просто вкладкой», ключ может исчезнуть сам — а вместе с
ним деньги. В кошельке есть кнопка «Сохранить ключ» (файл) и «Восстановить».

Чего в веб-версии на iOS не будет: **сканирования QR камерой**. В Safari нет
`BarcodeDetector`, поэтому кнопка сканирования там скрыта, а адрес вставляется
вручную. Ровно это и добавляет нативное приложение.

## Что даёт нативное приложение

| | PWA на iOS | это приложение |
|---|---|---|
| кошелёк, подпись, QR своего адреса | да | да |
| работа без сети | да | да |
| сканирование QR камерой | **нет** | да (AVFoundation) |
| ссылки `bhydra:` из системной «Камеры» | нет | да |
| раздача файлом | нет | да (с учётной записью Apple) |

Криптографии в нативном коде нет: ключ, подпись и QR считает та же страница
кошелька внутри `WKWebView`. Вторая реализация подписи под iOS была бы
ЧЕТВЁРТЫМ независимым кодом для одного формата (после Python, JS и C++) — и
четвёртым источником расхождений.

## Сборка (нужен Mac)

```bash
brew install xcodegen          # .xcodeproj генерируется, а не хранится
cd ios && xcodegen             # → BHydraWallet.xcodeproj
open BHydraWallet.xcodeproj
```

В Xcode: выберите свою команду в *Signing & Capabilities* → запустите на
устройстве. **Бесплатной учётной записи Apple достаточно**, но приложение,
подписанное ею, перестаёт запускаться через 7 дней и его нужно переустанавливать.
Платная (99 $/год) снимает срок и позволяет раздавать сборку через TestFlight.

Без XcodeGen: *File → New → Project → App*, назвать `BHydraWallet`, затем
перетащить в проект файлы из `BHydraWallet/` и заменить `Info.plist`.

Что важно в `Info.plist` и легко упустить:

* `NSCameraUsageDescription` — **без этого текста приложение падает** при
  первом обращении к камере, а не просто получает отказ;
* `NSAllowsLocalNetworking` — iOS запрещает открытый HTTP, а узел в домашней
  сети обычно отвечает именно по нему. Открыты только локальные адреса;
* `CFBundleURLSchemes: bhydra` — по этой схеме системная «Камера» открывает
  кошелёк, отсканировав чужой QR.

## Чего здесь нет

* Проверенной сборки — см. предупреждение в начале.
* Уведомлений о входящих платежах: нужен фоновый опрос узла и разрешение.
* Защиты Face ID / Touch ID. Ключ лежит в хранилище `WKWebView` открытым, как
  и в браузере. Это следующий шаг — и для PWA, и для обоих приложений.
